# FMODD 前端生成与界面秩序规范

> 状态：当前规范
> 适用范围：`src/web/index.html`、`src/web/app.css`、`src/web/dark-theme.css`、`src/web/app.js` 中新增或修改的用户界面
> 目的：让 FMODD 的功能增长保持统一、可识别，并避免回到通用 AI Dashboard 风格。

## 1. 产品视觉主张

FMODD 是 Football Manager 的本地俱乐部工作台，核心体验是读取、比较、判断和执行足球数据操作。

前端应当接近：

- Football Manager 的管理工具
- 体育数据终端
- 有明确足球语义的桌面应用

前端不应当接近：

- 通用 SaaS 仪表盘
- AI 产品落地页
- 电商卡片墙
- 只展示功能而不帮助用户完成工作的视觉稿

个性化来自信息组织、足球语义、数据密度和稳定的交互习惯，不来自装饰数量。

## 2. 绝对规则

新增界面默认禁止以下模式；只有明确的业务语义和书面理由才能例外：

- “图标 + 标题 + 说明 + 按钮”作为所有功能的默认结构
- 三列或四列等宽卡片墙
- 每个容器都加阴影、渐变或玻璃模糊
- 装饰性图标圆 pill、无意义徽章、悬浮按钮
- 标题或卡片左侧的装饰性强调边线
- 所有元素使用同一个大圆角
- 用超粗字重、渐变文字或发光效果制造层级
- 用颜色代替文字、位置或形状表达状态
- 为了“看起来丰富”增加没有信息含义的图形

尤其不要把新的页面机械套入现有卡片模板。先决定用户要完成什么，再决定容器。

## 3. 信息层级

每个页面和组件都按以下顺序组织：

1. 用户当前要完成的动作
2. 完成动作所需的主数据
3. 状态、时间、来源和限制
4. 次要说明、帮助和恢复操作

标题不重复说明文字。只有用户不能从界面推断出的风险、限制、等待或恢复信息才显示说明。

数字、赔率、比分、日期和球队名优先于装饰性标题。

## 4. 布局选择

| 内容性质 | 首选结构 | 不要默认使用 |
| --- | --- | --- |
| 赛程、积分、球员、职员、历史记录 | 表格或紧凑数据行 | 信息卡片墙 |
| 赔率选项 | 分组盘口面板、横向选项行 | 每个选项一张独立卡片 |
| 投注单、复杂表单、独立数据块 | 面板或有限数量的卡片 | 嵌套卡片 |
| 筛选和批量操作 | 工具栏 | 分散在多个卡片底部的按钮 |
| 短确认、少量输入 | 弹窗 | 用弹窗承载完整页面 |
| 需要持续对照的内容 | 同屏双栏或表格 | 藏在多层 Tabs 里 |
| 真实空间关系（球场、训练位置） | 空间布局 | 为了装饰而使用空间图 |

等宽列只有在数据确实同等重要时才使用。大多数页面应有明确的主列和辅助列。

## 5. ODD 的基础视觉语言

### 字体

当前基础字体栈为（可在“设置 → 显示”中为当前界面语言选择字体）：

```css
var(--fmodd-locale-font), var(--fmodd-english-render-font, var(--fmodd-english-font)), var(--fmodd-english-font), var(--fmodd-chinese-font), sans-serif
```

简体中文、繁体中文、韩语和日语界面所选的字体不会直接写进字体栈，而是先按选择生成一个仅覆盖 CJK 区段（汉字、假名、谚文、全角符号）的 `@font-face`：内置字体使用 `src:local(...)`，用户自定义字体使用 `/api/font-file` 地址；该 face 再放在栈首。原因是 Chromium 在 Windows 上会在第一个被判定覆盖 CJK 的字族处停止匹配（Segoe UI 通过系统字体链接被视为覆盖汉字），若把英文渲染字体放在前方，中文与用户字体会被静默忽略、汉字始终回退系统默认字体。限定区段后，汉字、假名与谚文使用所选字体，字母与数字继续使用英文/数字字体，两者的选择互不覆盖。

字体设置按界面语言保存在本机 `localStorage`，切换语言不会覆盖其他语言的选择。简体中文、繁体中文、韩语和日语界面同时显示两组选项：当前 CJK 文字系统的字体，以及共用的英文字母与数字字体；渲染时限制拉丁字体优先覆盖 Latin、数字和常用符号，CJK 字形继续由当前语言字体承担。其他语言只显示当前界面语言的字体选项。简体中文默认 `Microsoft YaHei UI`，繁体中文默认 `Microsoft JhengHei`，韩语默认 `Malgun Gothic`，日语默认 `Yu Gothic UI`，英文、德语、西语、法语和俄语默认 `Segoe UI`；各自下拉框只列出适合该文字系统的常见 Windows 字体及明确的 Noto/Source Han 回退候选。未安装字体由系统字体栈回退，不改变存档数据。旧版简体中文和英文的本地字体偏好会迁移到对应语言，CJK 混排中的拉丁字体沿用英文偏好。设置另提供六档字号滑块（默认第三档）。

除内置字体外，用户还可把自定义字体文件放入数据根下的 `fonts/chinese`（简体中文）与 `fonts/latin`（英文与数字）两个目录，支持 `.ttf`、`.otf`、`.ttc`、`.woff`、`.woff2`，目录由服务按需创建。字体设置中的“刷新字体列表”按钮会重新扫描两个目录、清空系统字体可用性缓存、刷新两组字体下拉框，并显示两个目录的绝对路径。用户字体按文件名排序、排在各自下拉框末尾，通过本地只读接口 `GET /api/font-file` 加载，只影响本机显示，不写入游戏内存或存档。

界面语言支持 English、简体中文、繁體中文、한국어、Deutsch、Español、Français、Русский、日本語、Português (Brasil) 与 Português (Portugal)。全新安装默认英文，升级前已存在但没有语言字段的设置保持简体中文；语言切换在当前页面原地生效，不刷新页面、不清空投注选择或未提交输入。英文是缺失翻译的统一回退，球队、球员、自定义名称和其他游戏事实不做通用翻译。

规则：

- 用户可见文字不得小于 `13px`
- 正文通常使用 400–500
- 标题通常使用 600–700
- 800/900 只用于确实需要强调的比分、赔率、结果或品牌标记
- 持续变化的数字使用 `font-variant-numeric: tabular-nums`
- 不为单个页面随意引入新字体；如需品牌字体，必须说明作用范围和回退字体

### 数字与金额单位

金额、市值与价格的大额显示使用紧凑单位，两套体系由“设置 → 显示”的「中文数字单位」开关切换（`#chinese-money-units`，键 `fm-odds-chinese-money-units`，未存储时按界面语言决定，中文界面默认开启）：

- 英文阶梯按 10^3 递进：K、M、B、T、P、E、Z、Y、R、Q。
- 中文阶梯按 10^4 递进：万、亿、兆、京、垓、秭、穰、沟、涧、正、载、极，覆盖到 10^48；这里的“兆”按万进读作 10^12，不是短级制的 10^6。

两套单位都保留一位小数。金额输入框接受同样的后缀，中文单位下可以输入 `1.5亿`；银行账单等需要精确数字的场景继续使用完整格式。行情图使用 K 线蜡烛图：实体表示当日涨跌、上下影线表示日内高低、成交量另起一栏，交互图提供十字线与悬停读数，红绿语义与利润/损失颜色保持一致。

### 颜色

- 绿色是 ODD 的主要行动和正向状态色
- 金色只表示重要性、荣誉、选中或稀缺资源，不作为装饰线填满页面
- 红色表示风险、失败或损失
- 灰色和背景色负责分组，不要让每个模块都拥有独立的高饱和颜色
- 状态不能只靠颜色表达，必须同时有文字、图标、位置或形状

### 边框、圆角和阴影

- 结构性表格、导航和数据行优先使用分隔线或留白
- 输入和紧凑按钮使用小圆角（约 3–5px）
- 普通面板使用中等圆角（约 6–8px）
- 大圆角只用于真正的特色场景，不作为全局默认
- 阴影只表示真实的层级关系；平面内容不要用阴影强行分组
- 不使用装饰性左边线、霓虹边框或彩色光晕

## 6. 组件规则

### 导航

导航首先保证名称、顺序和当前状态清楚。图标是辅助信息，不得代替文字，也不应每个入口都为了“完整”强行配图标。

### 工具栏

工具栏集中筛选、范围、刷新和批量操作。控件按操作顺序排列，避免一个页面出现多个互相竞争的主按钮。

### 页面标题

标题只回答“这里是什么”。当前范围、连接状态、更新时间和危险提示放在标题旁边或下方，不要堆成营销式副标题。

### 数据行

数据行应保持列对齐、数字稳定和快速扫描。优先使用轻分隔线、交替背景或选中背景表达层级，不要给每一行套一张卡片。

### 公告板

公告按固定三段顺序展示：永久公告、其他置顶公告、普通公告；同一段内按日期时间倒序，读者可切到“最新优先”，此时置顶不再优先，但永久公告仍固定第一。永久公告使用稳定公告键识别，后续新增版本公告或其他置顶公告只能排在其下方。置顶标签是状态提示，不能替代排序实现。

正文使用 Markdown 子集（多级标题、段落、列表、引用、分隔线、表格、代码、链接与图片）。卡片标题是 `h3`，正文标题只能落在 `h4`–`h6`，不得与弹窗 `h2` 争夺层级；链接只允许 http(s)，正文统一由渲染器转义。

图片必须来自打包内的 `/assets/` 路径或显式 `https://`，拒绝 `data:`、`javascript:` 与相对路径穿越；独立成行的图片渲染为带回形的 `figure` 和 `figcaption`，行内图片渲染为 `img`，两者都强制 `alt` 与懒加载。二维码等需要扫描的图片放在独立短卡片里（`alwaysOpen`），不使用长公告折叠区域承载；单张显示宽度不超过 280px，两张码并排时各占一列（桌面约 287px），窄屏 ≤560px 降为单列，保持可扫码的对比度与留白。

状态标签（发布、新增、优化、修复、重要、说明、活动、指南）必须同时给出文字，不能只靠颜色表达状态；标签同时作为筛选维度。工具栏按“标签筛选 → 搜索 → 排序”排列，筛选和搜索只影响当前展示，不改变公告数据、置顶规则或未读判定。

弹窗头部提供「不再提醒」勾选：未勾选时每次启动都自动弹出，勾选后只在出现新公告时弹出；手动点击顶栏「公告」始终可以打开。勾选状态只存在本机，不改变公告内容、排序或未读判定。

折叠以纯文本长度和块数量判定，但所有可折叠卡片统一使用 `--announcement-collapsed-height`（220px）的可视高度：收起时高度一致，展开后移除高度限制并完整显示全文。展开按钮带 `aria-expanded` 与 `aria-controls`；未读红点以日期时间最新的公告判定，而不是数组顺序。筛选和搜索每次打开公告板时重置，避免旧条件遮住新公告。

### 按钮

- 主按钮：一个页面或一个明确工作区最多一个主要动作
- 次按钮：描边或低对比背景
- 文字操作：用于低风险、可逆或辅助动作
- 危险操作：明确写出动作，不使用只有图标的危险按钮
- 图标按钮必须有可访问名称和可见焦点状态

### 空、忙、错和恢复状态

每个新数据区都要考虑：加载中、空结果、错误、忙碌、选中、禁用和恢复。不要用全屏 spinner 掩盖一个局部查询，也不要吞掉错误原因。

## 7. ODD 页面个性化边界

共享基础规则，但不同页面要保留自己的工作语义：

- 投注：赛程行、盘口分组、赔率选择和投注单是主结构
- 积分榜：表头、排名、状态和调整记录是主结构；不得仅凭固定名次区间渲染冠军、晋级或降级颜色，玩家执教球队可保留身份高亮；页面右上角的手动刷新调用积分榜刷新入口并复用共享刷新忙碌状态，刷新中禁用并公开 `aria-busy`
- 球队/球员：紧凑身份摘要 + 可扫描的数据列表
- 训练场：只有位置和空间关系是真实需求时才使用球场布局
- 银行/商店：金额、成本、限制和结果优先于商品卡片装饰
- 名人堂：可以使用更有历史感的字体和材质，但不得改变基础可读性和状态语义

如果一个新页面可以原封不动地改名为“CRM、AI SaaS 或银行后台”，说明它还没有体现 ODD 的领域语义。

## 8. 前端生成协议

任何新增或重做前端内容，在写代码前先写出以下五项（可放在任务说明、PR 描述或实现注释中）：

1. 页面工作：用户在这里要完成什么？
2. 主数据：用户第一眼必须看到什么？
3. 布局选择：为什么使用表格、列表、面板或卡片？
4. ODD 特征：这个页面通过什么足球语义与其他工具区分？
5. 禁止动作：本页明确不使用哪些通用模板手法？

实现时优先复用现有变量和组件。新增颜色、字体、圆角、阴影或动画时，必须能说明其业务作用。

## 9. 交付前检查清单

- [ ] 页面主要动作是否明显且只有一个主路径？
- [ ] 主数据是否比装饰性标题更突出？
- [ ] 是否不必要地把内容包装成卡片？
- [ ] 是否出现了图标 + 标题 + 说明 + 按钮的重复模板？
- [ ] 是否出现无语义的渐变、阴影、徽章、圆角或边线？
- [ ] 表格和数字是否容易扫描、对齐且使用稳定数字宽度？
- [ ] 选中、忙碌、错误和禁用状态是否清楚并可恢复？
- [ ] 深色主题、键盘焦点和最小字号是否保持一致？
- [ ] 页面是否有明确的 FM/足球工作语义？
- [ ] 如果去掉所有图标和装饰，信息结构是否仍然成立？

这份规范是当前前端生成的长期基线。设计研究、截图参考和一次性迭代记录不能替代它；若长期规则改变，应直接更新本文件并说明变更原因。

- 背包新增直接目标选择 dialog（`.inventory-target-dialog`），用于礼物赠送给 NPC 和成长仙丹选择孩子。
- 家庭卡新增 `CA / PA / 位置` 徽标与可折叠足球培养记录；事件弹层支持 `child_football` 的 6 个培养方向。
- 资产城市/城区分组改为「打开城市只展开城区标题，打开城区只展开本城区卡片」的两级展开语义。

### V2.9.4 商店与家庭补充

- 商店顶部品类栏按「全部 / 比赛 / 属性 / 声望 / 积分 / 子女」切换；情感/成人商品不再出现在商店，统一进入礼品精品店「情趣」。
- 礼品精品店每个品类至少两件礼物，底部新增购物车（数量、删除、合计、统一结算）。
- 家庭页为三列统计仪表盘 + 子女成长时间线；3/6/9/12 岁节点显示完成/可培养/错过，点击节点或「成长档案」展开姓名、培养历史、道具与试训。
- 15 岁后不再直接出现青训归属按钮，改为选择俱乐部试训；试训通过进入 `training`，失败 90 天后可重试，低级别俱乐部同样可选。

- 礼品精品店卡面按 SKU 取图标（`SKU_ICONS`），不再整类共用火焰；家庭页使用 `.interaction-family-layout` 左右分栏。
